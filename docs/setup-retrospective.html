A 组 · 脚本自身的坑（P1–P2、P10–P11）

P1

PowerShell 报"参数列表中缺少参量"，满屏乱码

症状
脚本第 44 行中文变成 閫氳繃 winget 瀹夎...，紧接着报出引号缺失、语句块不完整等一串解析错误。
根因
字符编码不匹配。脚本文件存的是 UTF-8 不带 BOM，而中文版 Windows PowerShell 5.1 在没有 BOM 时默认按 GBK 解码。中文被错解成乱码后，某些字节序列恰好"吃掉"了字符串的引号，导致语法解析崩溃。
解法
给 .ps1 文件头部加 UTF-8 BOM（字节 EF BB BF）。BOM 是一个"我是 UTF-8"的标记，PowerShell 见到它就按正确编码解析。加完用 [Parser]::ParseFile() 做语法校验，确认 0 错误。
大白话
相当于给中文文件贴了张"请用中文读我"的标签。不贴标签，系统就按英文规则硬读，读出一堆鬼画符，连带把标点也搞乱了。
P2

脚本一启动就退出，提示"需要管理员身份"

症状
普通 PowerShell 窗口运行脚本，检测到非管理员后直接 exit 1，需要用户手动重开管理员窗口。
根因
安装 Docker Desktop 需要管理员权限（要写系统目录、注册服务）。原脚本用 WindowsPrincipal.IsInRole() 判断权限，不满足就中止——逻辑正确但体验差。
解法
改为自动提权：检测到非管理员时，用 Start-Process pwsh -Verb RunAs 弹出 UAC（用户账户控制）授权框，用户点"是"后脚本以管理员身份重启自身，流程无缝继续。
大白话
原来像保安拦下你说"你没权限，自己去找经理"，改成像保安直接给你开门并帮你叫了经理，你点个头就行。
P10

Qdrant 容器永远显示 unhealthy，健康检查一直失败

症状
Qdrant 容器在跑、gRPC 端口探测通过，但 REST 端点验证失败，容器状态始终不是 healthy。
根因
两个独立的 bug 撞在一起：
① compose 里的健康检查命令用了 wget，但 Qdrant 官方镜像里根本没装 wget（它是精简镜像），命令必然执行失败；
② 验证脚本在 /healthz 的返回内容里找字符串 ok，而 Qdrant 实际返回的是 healthz check passed——关键词永远匹配不上。
解法
① 用容器内确实存在的 bash 写 TCP 探针替代 wget；② 把判定逻辑从"内容包含 ok"改为"HTTP 状态码 200"——这是更严谨的健康判定方式，不依赖服务方自由编写的响应文本。
大白话
第一个问题是"用一把不存在的钥匙去开锁"；第二个是"门其实开了，但你死盯着门牌上写不写'欢迎'两个字"。判"门能不能开"（状态码 200）比判"门牌写了啥"（内容含 ok）靠谱得多。
P11

镜像全部拉取失败，脚本却打印"环境已就绪"

症状
截图里四个服务全部报错 no such host，但脚本最后一行仍然输出绿色的 [ OK ] RAG 基础环境已就绪!——假的成功。
根因
脚本调用外部命令后没有检查退出码。docker compose pull 失败只体现在输出文本里，脚本自身的执行流并不感知，于是继续往下走并打印成功信息。
解法
在每次关键外部调用后校验 $LASTEXITCODE；pull 失败则直接终止并提示"请配置镜像加速器"；verify 脚本的失败计数也会向上传递，最终汇总的结论与真实状态一致。
大白话
原来像"外卖没送到，但系统照样弹'已送达'"。加退出码检查就是让脚本真的看一眼结果，别闭着眼睛报喜。

B 组 · Windows 与 Docker 环境的坑（P3–P6）

P3

Docker Desktop 无法由我自动安装

症状
用户期望"安装"是真实动作，但我无法直接完成。
根因
Docker Desktop 是 GUI 安装程序，需要管理员权限，并会修改系统级状态（注册 Windows 服务、启用 Hyper-V/虚拟化组件、注册 WSL2 发行版）。这类全局系统变更不允许在受限环境中静默执行。
解法
改用 winget（Windows 官方包管理器）在用户自己的终端里执行 winget install --id Docker.DockerDesktop，把下载、校验、静默安装全部自动化，用户只需要在终端里确认一次。
大白话
我不能替你在自己家里拆墙装门（那是你家的结构），但我可以帮你把装修队叫到门口，你开个门就行。
P4

Docker Desktop 启动后要求安装 WSL2

症状
Docker Desktop 首次启动弹出提示：缺少 WSL2 内核。
根因
Docker 容器跑的镜像是 Linux 程序（postgres、redis、qdrant 官方镜像都是 Linux 构建），需要 Linux 内核才能运行。Windows 内核跑不了 Linux 程序，必须由 WSL2（Windows Subsystem for Linux 2，微软官方的轻量 Linux 虚拟机）提供这一层。Docker Desktop 从 2023 年起已把老的 Hyper-V 后端标为废弃，默认只走 WSL2。
解法
管理员权限执行 wsl --install，启用虚拟化平台并安装内核，然后重启。
大白话
不是要你去"用 Linux"，而是给 Docker 准备一间能做"Linux 菜"的小厨房。你照常点菜，厨房在后台默默工作。
P5

WSL 内核装好了，但 Linux 发行版下载超时

症状
已安装 适用于 Linux 的 Windows 子系统 2.7.14，但接着报 无法从 raw.githubusercontent.com 提取通讯组列表，错误代码 WINET_E_TIMEOUT。
根因
WSL 安装默认发行版时，需要从 GitHub 的 raw 内容域名拉取发行版清单。raw.githubusercontent.com 在国内网络环境下经常超时或被阻断。
解法
绕过发行版清单机制，直接用微软官方直链下载 Ubuntu 的 appx 安装包（https://aka.ms/wslubuntu，也可用 azureedge 镜像直链），再用 Add-AppxPackage 本地安装。
大白话
自动售货机（WSL 清单）坏了，改成直接去仓库搬一箱货回来。
P6

安装 Ubuntu 报 0x80071772 / 注册失败

症状
Add-AppxPackage 看似执行完，但 wsl -l -v 显示没有任何已安装的发行版。
根因
Windows 的"新应用安装位置"被设成了非系统盘。WSL 的发行版注册流程对安装位置有特殊要求（其虚拟磁盘与注册信息默认需要落在系统盘），指向非系统盘时会注册失败。
解法
两条路径：方案 A—临时把"新应用将保存到"改回 C 盘，安装完成后随时改回去（该设置只影响之后新装的应用，不会搬走已装内容）；方案 B（绕开该设置）— 下载 Ubuntu 根文件系统 tar 包，用 wsl --import Ubuntu D:\WSL\Ubuntu <tar> --version 2 直接导入到指定目录。
大白话
这个设置相当于"新买的东西默认放哪个柜子"。WSL 的执照必须放在系统指定的柜子里，你却把它指到了另一个柜子，于是登记不上。要么临时把默认柜子改回来，要么跳过登记直接搬运。

C 组 · 网络与镜像源的坑（P7–P9）

P7

镜像全部拉取失败：no such host

症状
四个服务全部启动失败，报 failed to resolve registry-1.docker.io、no such host。
根因
Docker Hub 的镜像下载域名在国内网络下不可达。Docker 默认从 registry-1.docker.io 拉取镜像，该域名长期受限，导致 DNS 解析失败或连接超时。
解法
在 Docker Desktop 的 Docker Engine 配置里加入 registry-mirrors（镜像加速器）列表，把拉取请求指向国内可访问的中转服务。配置格式为 JSON，改完需 Apply & Restart 使 Dockerd 重新加载。
大白话
原来要从"国外总店"发货，快递不通。加镜像加速器等于在国内设个中转仓，你在中转仓取货。
P8

配置的加速器全部失效（域名都解析不了）

症状
配置了中科大、网易、百度三个公开加速器后，仍然 no such host——连加速器的域名都解析失败。
根因
这些公开免费加速器已陆续停止服务。国内外大量旧教程仍在引用它们，但服务实际早已下线，域名和 IP 都不再响应。
解法
改用各家云厂商的专属加速器（阿里云容器镜像服务为每个账号免费提供独立的加速地址）。这是目前最稳定的方案，但需要用户自行登录云账号领取。
大白话
网上教程抄的是几年前的地图，上面的公交线路早停运了。得去问当地最新的官方线路表。
P9

加速器地址配了两处错：重复前缀 + 域名叠加

症状
请求 URL 变成 https://https://4gviicxi9.mirror.aliyuncs.com.mirror.aliyuncs.com/...，返回 403。
根因
复制粘贴两次错误叠加：① 配置值里多写了一层 https:// 协议头（JSON 值本身已是完整 URL，不允许再加）；② 域名后缀 .mirror.aliyuncs.com 出现了两遍——很可能是复制时把控制台里展示的完整地址与已带后缀的部分拼接了两次。
解法
只保留一行、只写一次协议头、只写一次域名后缀："https://4gviicxi9.mirror.aliyuncs.com"。
大白话
写信地址栏填成了"中国中国北京市北京市……"，邮局当然投不出去。
P9+

阿里云加速器返回 403（附带发现）

症状
地址修正后连通但返回 403 Forbidden，说明服务器可达但拒绝代理请求。
根因
该账号未开通容器镜像服务，或云厂商已收紧免费 Docker Hub 代理策略。
解法
换用社区维护的中转代理组合（daocloud、1panel、rat.dev、上海交大镜像站等），最终 docker pull hello-world 成功——先用一个体积最小的镜像验证通道，再跑完整拉取，避免浪费时间在几 GB 的镜像上试错。
大白话
先寄一张明信片试试路通不通，通了再寄大箱子。

D 组 · Git 与 GitHub 的坑（P12–P16）

P12

PowerShell 里"找不到 git 命令"

症状
git : 无法将"git"项识别为 cmdlet…，但 git 明明装着（我一直在用）。
根因
PATH 环境变量未包含 git 可执行文件所在目录。本机的 git 是随工具链附带的便携版（PortableGit），位于 C:\Users\w1143\.workbuddy\binaries\PortableGit\versions\1.2.0\cmd，该路径没有写入用户级 PATH，所以普通终端"看不见"它。
解法
用 [Environment]::SetEnvironmentVariable("Path", ..., "User") 把该目录追加进用户级 PATH（不动系统级 PATH，避免影响其他程序），然后重启终端使新环境变量生效。
大白话
工具放在仓库里，但你的通讯录里没登记它的号码，所以叫不出来。把它加进通讯录（PATH），并且要重新打开电话簿（重启终端）才生效。
P13

git push 报 CRYPT_E_NO_REVOCATION_CHECK (0x80092012)

症状
推送时报"吊销功能无法检查证书是否吊销"，HTTPS 握手失败。
根因
Windows 的 TLS 组件（schannel）在校验证书时，需要联网向 CA 的 OCSP/CRL 服务确认"这张证书有没有被吊销"。该网络路径不可达时，schannel 出于安全考虑直接判定握手失败——保守失败策略。
解法
两条命令切换 TLS 行为：
git config --global http.schannelCheckRevoke false（跳过吊销状态查询）
git config --global http.sslBackend openssl（改用 git 自带的 OpenSSL 后端替代系统 schannel）
大白话
门卫要打一个电话核实你的证件真伪，电话打不通，他就一律不放行。改成"电话打不通时按证件本身判断"即可。
P14

切换后端后新错：unable to get local issuer certificate

症状
改用 OpenSSL 后端后，报"无法获取本地颁发者证书"。
根因
OpenSSL 找不到 CA 根证书包（trust store）。schannel 用的是 Windows 系统证书库，而 OpenSSL 需要显式指定一个 ca-bundle.crt 文件。便携版 Git 不会自动指向自带的证书包，于是无法构建完整的证书链。
解法
显式指定证书包路径：
git config --global http.sslCAInfo "C:\...\PortableGit\versions\1.2.0\mingw64\etc\ssl\certs\ca-bundle.crt"
大白话
新门卫不认市政府发的公章，你得告诉他"公章样本册放在这格柜子里"。
P15

弹窗问"凭证存哪里"（Select a credential helper）

性质
这不是错误，是 Git for Windows 的首次交互引导。
解法
选择 manager（Git Credential Manager）并勾选 Always use this from now on，让系统安全地记住凭证，后续推送不再反复输入。
大白话
银行问你要不要开通"免密记忆"服务。勾上，下次不用再输。
P16

GitHub 不再接受账号密码直接推送

背景
GitHub 自 2021 年起取消了对"账号 + 登录密码"的 HTTPS 推送支持。
解法
改用 Personal Access Token（PAT）：在 GitHub 设置里生成一个有 repo 权限的令牌，推送时把令牌当作密码输入。更顺滑的方式是走 Credential Manager 的浏览器授权流程。
大白话
以前进楼用身份证（密码），现在要专用门禁卡（Token）。卡能设有效期、能随时注销，比身份证安全。

5术语速查表

左边是专业说法，右边是大白话。以后看文档、搜报错都用得上。

容器 / Container
把应用和它的运行环境（依赖库、配置）打包成一个标准化单元，在任何支持容器的机器上行为一致。
像"预制菜"——食材、调料、火候全封装在盒子里，走到哪台灶上味道都一样。
镜像 / Image
容器的只读模板，包含文件系统与启动配置。容器是镜像的运行实例。
镜像是"菜谱 + 半成品"，容器是"按这份菜谱做出来正在吃的那一份"。
Docker Compose
用一个 YAML 文件声明多个容器的编排关系（镜像、端口、数据卷、依赖顺序、健康检查），一条命令全部拉起。
像"套餐下单"——一次点四个菜，后厨按菜单同时开工，不用一道一道喊。
WSL2
Windows Subsystem for Linux 2，基于 Hyper-V 的轻量虚拟化，提供真实 Linux 内核。
Windows 家里隔出来的"Linux 小厨房"，专门用来跑 Linux 程序。
健康检查 / healthcheck
Docker 按固定间隔执行的探测命令，用于判断服务是否真正可用，结果影响容器的 healthy / unhealthy 状态与依赖启动顺序。
定期给服务"量体温"，正常就挂绿牌，异常挂红牌，别的服务看牌决定要不要开始干活。
幂等 / Idempotent
同一操作执行一次与执行多次，对系统产生的最终状态相同。
电梯按钮——按一次和连按五次，电梯该来还是来一次。所以 bootstrap 脚本可以放心反复跑。
环境变量 / .env
以键值对形式向进程注入配置，避免把密钥、地址硬编码进代码。
写给程序看的"便签纸"，上面记着密码和地址。因为含密码，所以不放进代码仓库。
.gitignore
声明哪些文件不纳入版本控制。
"这些文件别拍进快照"的清单——用来挡住密钥、数据文件、缓存。
commit / 提交
把工作区当前的变更打包成一次带作者、时间、说明的历史记录存入版本库。
游戏存档点。随时可以读回任意一次存档，等于无限后悔药。
git 与 GitHub
git 是分布式的本地版本控制系统；GitHub 是托管 git 仓库的云端服务平台，通过 push / pull 同步。
git 是记账方法，GitHub 是用这套方法开的"云账本银行"。账本原件在你手里，银行存一份备份还能给别人看。
registry mirror / 镜像加速器
Docker 拉取镜像时的中转代理，缓解官方仓库在特定网络下不可达的问题。
国内中转仓。原厂发货太慢，先囤一批到国内，你从国内取。
BOM / 字节序标记
文件开头的 EF BB BF 字节，显式声明该文件为 UTF-8 编码。
贴在文件首页的"请按中文读我"标签，防止系统用错编码读出一堆乱码。
UAC / 用户账户控制
Windows 的权限提升机制，高风险操作必须由用户显式授权。
系统弹出的"是否允许此应用更改你的设备"弹窗，你点"是"才算授权。
向量数据库 / RAG
把文本转成高维向量存储，按语义相似度检索的数据库。RAG（检索增强生成）即"先检索相关知识、再让大模型基于检索结果作答"。
普通搜索靠"字面匹配"，它靠"意思相近"。RAG 就是让 AI 答题前先翻一遍你给的资料，而不是凭记忆瞎说。
